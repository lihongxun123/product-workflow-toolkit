# 中文文档编辑

让读者容易理解、判断和执行。按当前项目的用途、术语与样本写作，维护已有主稿；新写交付到用户指定的位置或直接在对话中呈现。

随包文件路径相对于当前 Skill 目录。用户需要阅读参考正文或体验案例时，从随附文件读取对应内容，按需要展示或导出。

## 确定任务与材料

- **只读审校**：用户要求检测、评估或只标问题时，给出位置、原因和建议。
- **编辑或成稿**：按已授权范围直接完成。保留自然、准确的内容；结构妨碍阅读时可重组，不为显得改动充分而整篇重写。
- **批量整理**：先定位有效主稿与实际文体，按模块或文体推进；已有认可样本直接复用。方法未稳定时先做代表性样本并自检，再继续已授权范围；用户要求先审样时才在样本处等待。

从目标材料、适用的 AGENTS.md 和当前决定中提取读者、用途、范围与状态；只补查会影响本次交付的信息。关键事实冲突先核对当前来源；缺少会改变方向的输入时简短询问，其余部分继续处理。

## 八条行文标准

1. **行文简洁。** 删套话、重复解释、空泛评价和过程流水。一段讲清一个意思；必要的承接和解释可以保留，不以字数或删减比例衡量质量。
2. **不写防御性文案。** 删自我辩护、反复免责和与读者无关的“未做什么”。影响判断或执行的真实限制在相关位置说明清楚；共用限制集中一次，必要例外就近说明。
3. **直接写事实、规则和结果。** 写清谁对什么做什么、何时生效及处理结果，不用“能力、承接、闭环”等抽象词代替动作，也不靠斜杠和内部简称压缩句子。正文和链接文字优先用业务名称；必要追踪编号保留在管理信息中。准确专业词可以保留，首次出现按读者需要说明含义，不机械换词。能直接说明成功条件时，不再反复罗列什么“不代表成功”。
4. **按读者使用顺序组织。** 先回答读者要解决的问题，再展开所需说明。费用、权限、适用条件放在对应操作或结论附近；工作日志和编辑过程留在交付正文之外。
5. **共用规则集中写，例外单独说明。** 同一规则维护一处，其他位置按需引用或保留理解当前步骤所需的简短提示。验收写如何判断通过，不整段复述需求。
6. **精简不损失必要信息。** 保留影响理解、决策、实施和验收的事实、依据、字段、条件及异常处理。背景推导和历史细节按需引用，不为精简删掉关键反例。
7. **事实与状态准确。** 区分事实、推断和假设，以及已确认、待定、已验证和待验。保留证据的确定程度及适用范围；新写也须依据材料，不补造数据、引述、效果或完成状态。
8. **结构适合内容。** 并列用列表，对比用表格，解释用自然段。沿用适用样本的信息密度和表达方式，不照搬其章节、篇幅、事实或品牌口吻。

自检：删掉一句话，是否影响读者理解、决策、执行或验收？不影响就删，有影响就写具体。真实的禁止条件、风险提示和责任说明按用途保留，不能按否定词机械删除。

## 按文体调整

- **需求与规范**：写清用户问题、范围、规则、状态、异常和验收。保持中性、直接，保留规范强度。
- **SOP 与指南**：沿实际操作顺序写步骤、结果和异常；角色、输入、权限等仅在会影响执行时展开，不给每步套齐所有栏目。
- **调研与决策材料**：用具体观察支持判断，说明证据对决策的意义，关键限制紧邻结论。详细方法与来源按需放在已有证据区或附录。
- **公开文案**：说明用户价值和下一步，语气遵循当前品牌；利益点须有依据，内部流程仅在帮助用户决定时出现。
- **历史与状态材料**：保留时间、阶段、来源及当时判断，不把历史方案写成当前决定，也不把多个阶段拼成未经证实的因果链。

## 编辑与核对

按本次影响识别要保护的信息，简单编辑直接对照原文，复杂改写可在内部列清单：

- 名称、对象、模块、版本、日期、数值、单位、负责人及适用范围；
- 强制、禁止、默认、排除、上下限等规则含义（如“仅支持”不能简化成“支持”），以及费用、权限、异常、退出与验收条件；
- 事实与推断、历史与当前、设计与实际验证之间的区别；
- 原始引用、代码、命令、字段、模型 ID、路径、链接和锚点。

文字编辑默认保持上述内容及含义。若用户已要求修正其中的错误，核对依据后修改；未解决的疑点具体说明，不用顺滑措辞掩盖。新稿中的事实逐项有材料支持，精简稿不引入新的业务决定。

先处理误导事实或状态，再调整结构和句子。交付前同时检查意思是否准确、读者是否能用：对照原文核对范围、默认、计算依据、异常和例外；假设读者没看过聊天历史，沿一项具体任务阅读，检查是否还要猜编号、翻译术语或来回找规则才能决定下一步。改写不得把条件改成新公式、把处理范围缩成某一步；不能只凭字数减少、关键词保留或链接有效判定完成。

检查链接、表格和代码块；结构或排版变化时查看实际呈现，采用当前交付形式的检查方法。重排后核对标题层级、可见序号与正文引用；保留旧锚点不要求保留乱序标题。检查长表可读性及原始格式标记是否露出，解析成功不等于阅读通过。

批量任务覆盖本次实际存在的文体和高影响改写，局部改动检查受影响项。重要结论和大范围改写安排独立复核；不重复扩大已通过的检查。

## 按需参考与工具

- 需要判断冗余、防御性文案或具体改写方式时，读表达模式与改写示例（`references/chinese-ai-patterns.md`）。
- 需要品牌口径时，从目标项目的定位、术语和已认可样本提取规则。缺少项目样本时可参考虚构品牌行文示例（`references/brand-voice-example.md`）。
- 研究报告需要样本且当前项目没有更合适样本时，读研究报告样本（`references/research-report-examples.md`）。只借鉴写法，事实、定位和结论由当前材料支持。

批量初筛 Markdown 或文本时，可使用只读扫描器（`scripts/audit_chinese_ai_style.py`）：

```text
python "<本 Skill 目录>/scripts/audit_chinese_ai_style.py" "<目标文件或目录>" --format text
```

使用可用的 Python 环境运行；脚本路径从本 Skill 目录解析，目标路径明确指向本次范围。扫描结果只是候选问题，不判定作者身份或内容真伪；结合上下文处理，不追求命中数归零。普通小改无需运行，默认不增加 CI 门槛。

## 交付

只读审校列实际问题、位置和建议；编辑交付正文或已有文件，简述主要变化、实际核对和影响使用的剩余问题。用户只要正文时直接给正文，不附编辑过程、固定总结或无关免责声明。
