## 跟着案例练习

先只给 Codex 看观察记录，问「满员后怎么处理临时候补，有哪些产品取舍需要我决定？」然后用评审决定作为用户回复，让它输出范围、模拟场景与一条可验证的失败恢复。最后打开交互原型照验收路径操作，再将输出与需求、任务摘要对照。

例中的一句改稿是把「系统将在后续有机会的时候根据目前的相关规则进行相应的递补处理」改为「有空位时，工作人员按候补顺序递补。」这句保留了触发条件、角色和顺序。加入候补后的状态由页面单独显示。

直接用浏览器打开 `prototype.html`。刷新会重置示例；同一次页面会话中切换访客和工作人员，可从两端查看同一条模拟记录。
