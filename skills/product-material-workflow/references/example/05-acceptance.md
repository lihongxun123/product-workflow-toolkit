# 原型检查与生产验收

从 [交互原型](prototype.html) 进入。每次打开默认为满员、无人候补，示例活动有 2 个席位。页面顶端可切换两位访客和工作人员。侧栏的「释放一个名额」模拟原有取消预约，「模拟下一次保存失败」用于验证恢复。打开新页面或刷新可以重置。

| 路径 | 操作 | 应看到 |
| --- | --- | --- |
| 正常递补 | 分别让林予、潘禾加入候补。切到工作人员，释放一个名额，确认递补。 | 候补起初按两人的加入顺序排列。余位归零，林予看到「已预约」，潘禾看到「候补中」。 |
| 退出与重排 | 两人按同样顺序加入。林予退出，再在满员时加入。 | 工作人员看到潘禾在首位，林予在第二位。 |
| 队首变化 | 两人加入后释放名额，工作人员点击「递补队首」，先不确认。切到林予退出，再切回工作人员确认。 | 页面提示队列已更新，余位保留。重新选择队首时目标为潘禾。 |
| 保存失败 | 满员时选中「模拟下一次保存失败」，让林予加入候补，再重试一次。 | 第一次显示重试提示，状态仍为未预约。第二次成功。 |
| 空位与权限 | 初始时释放一个名额，切到林予并直接预约。 | 活动显示「已有空位，可直接预约」，直接预约后显示「已预约」。访客视图无后台递补操作。 |
| 空位被直接预约 | 两位访客加入候补，释放一个名额，工作人员选择林予但暂不确认。切到潘禾直接预约，再切回工作人员确认。 | 潘禾已预约并移出队列，递补确认提示余位变化，林予仍在候补。 |

在手机宽度和键盘操作下复查按钮、反馈与确认步骤。原型展示角色差异和业务路径，真实登录、服务端鉴权、持久化、并发、重复请求和跨会话回读按 [需求主稿](03-requirement.md) 进入研发验收。
