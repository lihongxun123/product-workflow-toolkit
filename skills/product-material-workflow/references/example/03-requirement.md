# 活动候补与人工递补

当活动满员时，已登录访客可以登记候补并查看结果。活动出现空位后，负责本活动的工作人员可按加入顺序递补。范围包括活动详情与运营后台。原有直接预约、取消预约和查看其他活动沿用记录与入口。

## 访客加入和退出

- 活动开放预约且余位为 0 时，活动详情向未预约、未候补的访客提供「加入候补」。系统在提交时重新检查活动状态和余位。还有可预约名额时，提示「已有空位，可直接预约」并恢复已有预约入口。
- 候补不锁定余位。已有候补的访客可在空位出现时直接预约，成功提交时结束本人的候补。店员递补与直接预约使用同一余位，均在确认时重新检查。
- 按服务端接收成功的顺序排队，同一活动、同一账号最多有一条有效候补。重试或重复提交返回原有候补，不改变顺序。加入成功后活动详情显示「候补中」。
- 账号只可退出自己的有效候补。请求成功后退出队列。再次加入从队尾开始，仍需满足活动开放且满员的条件。
- 加入或退出提交失败时，显示可重试提示，服务端此前保存的状态继续有效。显示报名状态前按当前账号回读。

## 工作人员确认递补

- 有该活动管理权限的工作人员可见余位和候补队列。活动开放且有空位时，可选当前队首进入确认。
- 确认时重新检查活动状态、工作人员权限、最新余位及选中访客仍为队首。在同一次提交内消耗一个可用名额、写入已有报名记录并结束该访客的候补。成功后访客详情显示「已预约」，候补队列移除该访客。
- 队首已退出、空位被用完或活动已关闭时，确认失败，候补与报名记录按最新状态回读，操作人刷新后重新判断。服务端应保证并发确认只占用一次名额，重复请求可回读原结果。其他失败给出重试提示。

## 验收结果

| 给定条件与动作 | 可观察结果 |
| --- | --- |
| 满员活动中两位访客依次加入，首位重复提交 | 队列仅有两人且顺序不变。 |
| 队首退出并在满员时重新加入 | 第二位成为队首，重新加入的人排在队尾。 |
| 释放一个空位并确认递补 | 队首变为已预约，空位归零，下一位保留候补状态。 |
| 确认前选中的队首退出 | 提示队列变化，空位保留，工作人员需重新选择新队首再确认。 |
| 队首处于待确认递补时，另一位候补访客直接预约最后一个空位 | 直接预约者成为已预约并离开队列。原递补确认失败，原队首仍在候补。 |
| 提交失败或重复确认 | 失败时此前状态仍有效，可以重试。成功过的请求只生成一条报名。 |
| 普通访客发起后台操作，或两名工作人员争抢最后一个名额 | 后台拒绝无权限请求，最后一个席位只产生一条有效报名。 |
