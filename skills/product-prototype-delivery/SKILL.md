# 高保真产品原型生成与验收

沿用项目的技术栈和设计组件，在已授权的原型范围内实现并验证完整用户任务。修改业务源码或发布原型须有对应授权。

随包文件路径相对于当前 Skill 目录。用户需要阅读参考正文或体验案例时，从随附文件读取对应内容，按需要展示或导出。

## 确定实施依据

先定位本次修改采用的业务规则、视觉样板与组件契约，明确允许改变的部分及需保留的行为；核对目标目录和工作区状态，保留用户改动。已读取且仍适用的依据直接复用，只补查变化或缺口。这是代理内部实施准备，不要求另交计划表或例行请用户确认。

先观察当前页面，并找到最近的现有组件或页面实现；需要对齐线上时核对实际线上页面及对应源码，不以想象中的线上样式作为证据。无法访问时说明未核实部分，继续不依赖它的工作。

当前用户决定负责业务范围，当前有效设计契约负责视觉交互；历史原型和源码只证明其对应版本。现有实现与规则不一致时，先查明是遗漏、旧方案还是待定设计；代码或样例中存在不等于当前需求要求保留。依据明确的在授权内处理，只有无法自行消解的新取舍才交用户判断。竞品用于解决已识别问题，不能直接照搬其业务、数据和品牌样式。

## 按需查阅 Web 实现指南

新页面先复用项目已有组件。遇到新交互、浏览器 API、性能、无障碍或兼容性疑点时，先用随包指南（`references/web-implementation.md`）核对；已有适用结论可直接复用。仍需查证时，可用环境中已有的 `modern-web-guidance` 查具体问题。文案、颜色、间距和已有组件参数的小调整可直接处理。

## 从参考到高保真页面

先理解角色、任务和业务路径，明确用户要判断的信息与主要动作，再确定页面对象、分组和组件。新增页面、实体或配置前，判断现有业务能力能否承载，不把内部技术差异直接转成运营人员需要维护的选项。已有认可样板时复用其适用规则；新页面先读取设计包的当前入口和对应模式。

需要竞品参考时，围绕具体问题观察实际页面与关键状态，记录借鉴机制、适用条件及取舍。选定一致的视觉方向，把信息组织、密度或交互转译为本项目组件与主题。与既有理念冲突时，比较用户任务、业务规则、可读性、SEO 和维护成本；涉及产品范围或品牌方向的变化按已有授权处理，不把竞品做法直接升级为项目标准。

方法尚未稳定的多页任务，先用有依据、长度有代表性的内容完成一个样板。检查首屏与完整正文的主次、分组、对齐、字级、留白、边框、图标和控件细节，再看桌面与手机的阅读顺序及操作可达性。视觉验收同时判断是否清楚、协调、完整，不能停在无溢出或组件已复用。已有合适样板直接继续；用户要求先审样时按约定等待。

有源码或线上参考时，在可比环境下按相同内容、视口、主题、语言和状态观察实际渲染，对齐信息层级、字号、密度、对齐及抽屉、表格等细节，保留参考中仍需要的能力和信息。改版按影响对照前后及关键状态，发现问题后修正并复查相关路径；重要改版安排独立视觉与行为复核，普通局部修改按影响自检。

## 公开页面的 SEO 友好

从内容与布局设计阶段考虑搜索发现：清晰的页面主题和标题层级、有用正文、逐页元信息、有效页面链接，以及手机端等价关键信息。正文、标题、摘要和规范地址采用项目约定的同一内容来源。折叠、Tab 和视觉精简保留需收录内容，按项目技术契约检查首次 HTML 输出，不用关键词堆砌或虚构内容补足版面。

评审原型与正式公开页分别遵循项目索引规则；视觉样板通过后，技术 SEO 仍按相应环境验收，不为此自行改变预览的 noindex 或迁移框架。

## 减法优化

先判断用户要精简页面表达还是改变产品方案。文案、层级与视觉减法保留既定行为；删除功能、改变默认选择或移除后恢复等规则，须依据已确认决定。用户已批准具体删减建议时直接执行，不重复确认；仅审查或仅改文档不自动取得原型修改授权。

围绕用户主任务复用已有数据、能力和组件，减少重复维护、作用重叠的选项及不必要的分支，避免为假设风险堆叠配置和提示。保留必要的金额、权限、输入校验、失败恢复、历史与在途状态；精简运营界面不等于删除底层记录或放宽校验。

先用分组、位置和清晰的动作表达用途，删重复标题、无用解释和防御性文案；费用、单位、权限、限制及可行动提示放在相关内容旁。tooltip 只承载补充信息，不能替代必要标签与操作后果。

删减要贯通入口、控件、状态逻辑、持久化、重新进入或重新添加、消费该配置的页面，并同步对应需求与验收；不止隐藏按钮。用户指出一处问题时，检查同一组件或同一规则下的同类情况；已确认口径覆盖的在授权范围内一并修正，新取舍集中提出，不扩展为全站审查。正常编辑不得意外重置已保存值。

## 实现完整路径

- 写清受影响的入口 → 输入/选择 → 执行 → 结果 → 返回；仅在涉及时补登录续接、刷新、异步任务及外部跳转。
- 字段、标签、可选模型及能力由已核实数据或确认规则决定。展示和筛选采用相同来源，不能凭名称猜能力。
- 参数切换保留兼容输入；不兼容值按已确定规则处理。登录成功本身不应新增未授权的提交、付费或生成动作。
- 错误不能伪装为空数据，缺价不能当作免费；只有存在实际操作才设计相应状态，不为静态页面堆失败弹窗。
- 评审复用符合现行规则的样例；正常样例补齐该场景适用的基础信息，缺失数据另作为异常样例，不用旧样例的缺项代替产品展示规则。模拟数据明确标识，按真实业务路径流转；真实历史数据不补造。界面仅显示产品内容；模拟边界和验证记录放本地资料，模拟结果不声称为真实调用成功。
- 外链采用核实后的目标与约定行为，不用无效域名或通用演示弹窗代替已确认跳转。没有真实收银台等动态地址时说明缺口，使用已授权的衔接方案，不自行产生真实交易。

## 复用和视觉约束

优先改共享组件或参数，避免复制页面级 CSS 修补同一问题。使用项目现有图标、按钮、字体、间距、表格操作、卡片和主题变量；具体数值从设计包读取，不在技能里设通用像素值。

涉及操作反馈时，从项目设计包的反馈选型入口查对应组件，并核对当前实现的导出接口及现有调用示例；按操作结果的持续性选择气泡、字段或区域反馈。具体组件名、参数和例外留在项目设计包，不凭其他组件库的同名 API 推断用法。

同一语义的入口名称和图标一致；不同任务允许不同布局，不能为了“统一”把官网、控制台和后台抹成一种页面。复用组件也须检查所选变体和交互，不能仅凭组件名称宣布符合设计包。

## 验收与同步

实施前选取本次适用的验收检查项（`references/acceptance.md`），完成后用实际页面验证。按改动选择检查：间距调整看受影响布局，字段展示看相关状态，状态映射看列表、筛选与详情的一致性；共享组件和跨页主路径按依赖扩大范围。已有证据只有对应版本、环境和路径仍适用时才能复用。

视觉检查观察实际截图/页面；行为检查真实操作与结果，必要时核对请求。构建、静态扫描不能代替浏览器验证。对重要跨模块变化按项目要求做独立复核，明确实际复核范围。

同步对应本地需求的最终规则及现有验证入口，不生成冗长过程日志。用户确认视觉样板后，按授权把有效规则、适用范围和必要截图补入现有设计包，并更新入口与优先级，供后续生成使用；品牌、像素值和页面例外留在项目内，通用方法才进入 Skill。报告已改内容、验证环境与未验部分，不把用户审阅、下发、真实接口验收或部署写成已完成。

部署属于独立授权。若本次包含发布，必须在发布产物中验证主要流程，不依赖开发机端口、绝对路径或未打包模拟服务；推送和流水线成功均不能代替发布页验证。
